## 言語とは

ここでいう「言語」は自然言語ではなく、プログラミング言語や形式言語を指します。

- **無限個**の言葉（単語・語句）の集合
- **有限の文字**と**有限の構文規則**によって定義される文字列の集合

たとえば Quine は一見して Ruby に見えませんが、Ruby の言語として機能します。逆に見た目が Ruby っぽくても、`SyntaxError` になる文字列もあります。
この違いを定めるのが **構文規則・文法** です。

## 文法とは

- 言語を定義する**有限個のルール**の集合
- 言語に構造・秩序をもたらすもの

言語は無限個の言葉の集合なので、そのままではカオス。それを秩序だてるのが文法なんですね。

## オートマトンとは

基本情報技術者試験の状態遷移図として見たことがあるかもしれません。

- あるものの動作や構造を表現するもの
- **状態**を持ち、入力によって状態を**遷移**させる

たとえば「110円のみ受け付ける自動販売機」を考えると、「10円投入済み」「100円投入済み」「110円到達」のような状態遷移で表現できます。

![スライド：自動販売機のオートマトン](/images/white-and-black-door/automaton_vending-11.png)

A や B・C の時に購入ボタンを押しても反応しません。10円を入れた後にもう一度 10円を入れても受け付けません。

オートマトンには種類があり、後述しますが大きく以下の4つです。

| 種類 | 特徴 |
|---|---|
| 有限オートマトン | 有限個の状態と遷移 |
| プッシュダウン・オートマトン (PDA) | 有限オートマトン + スタック記憶領域 |
| 線形拘束オートマトン | 有限のテープ + 読み書きヘッド |
| チューリングマシン | 無限長のテープ + 読み書きヘッド |

## オートマトンと Parser の関係

- 言語は文法・構文によって秩序だてられる
- **Parser** は構文を司るオートマトン
- **Lexer** はトークン（語句）を司るオートマトン
- **Lrama** は `parse.y` に定義された Parser を生成する Parser Generator

ここまで聞いて「なるほど、わからん」となりました。
非常に興味深いセッションでしたが、 Parser とオートマトンの関係がまだ腹落ちしていない。
もっとちゃんと勉強しなければ、と思いました。

ちなみに私は「オートマトン」と聞くと、フィリップ・K・ディックの電気羊か、自動でジンギスカンを作るマシンを想像してしまいます。オートマタの単数形がオートマトンなんだそうです。

## 古代語と遺跡

物語にはこのような文字列が登場します。

```
I.   ●○○●
II.  ●○○●●○○●
III. ●○●○○○●○●●○●
```

これは **古代語** と呼ばれるもので、読み方や意味はわかりません。ただの記号の羅列に見えます。

しかし、以下のような規則に基づいていると捉えると、それは **形式言語** になります。

- 「偶数個の○と偶数個の●を持つ」
- 「○と●を任意の回数繰り返し、最後が○●で終わる」
- 「●から始まり●で終わる」

さらに物語には **「遺跡」** が登場します。白の扉と黒の扉があり、どちらかを開くとどこかの部屋へ移動する。間違った扉を選ぶと危険な目に遭う。遺跡に入ったり扉を選んだりすると持ち物が増えたり減ったりする……。

古代の妖精たちが自分たちの言語を表現するために遺跡を作ったという設定で、主人公の魔術師見習い ガレット が数々の遺跡を探検する中で、謎を解明し成長していく物語です。

![スライド：遺跡の構造](/images/white-and-black-door/ruins-18.png)

そしてこの **遺跡の構造がオートマトン** になっているんです。
入口が開始状態、出口が終了状態とすると、遺跡の構造はオートマトンそのものです。

# Lrama で言語判定器を作ってみた

理解を深めるために、物語に出てくる形式言語の Parser を Lrama で実際に作ってみました。

## 正則言語と有限オートマトン：第四十八古代ルル語

物語に登場する「第四十八古代ルル語」は以下のような言語です。
ここからは●を `1`、○を `0` に置き換えます。

```
I.   1001
II.  10011001
III. 101000101101
```

規則は「0 と 1 を任意の回数繰り返し、最後が `01` で終わる」です。
正規表現で書くと `^(0|1)*01$` のような感じです。

このように正規表現で表現できる言語を **正則言語** といい、有限個の状態を持つオートマトン（**有限オートマトン**）で表現できます。

### parse.y について

Lrama で `.y` ファイルを書いていくので、まず `parse.y` の構造を理解します。

```parse.y
declarations   ← 宣言部
%%
rules          ← 規則部
%%
programs       ← プログラム部
```

YACC（Yet Another Compiler Compiler）形式で記述された構文定義ファイルです。
宣言部とプログラム部はなくても成立し、規則部は BNF（Backus-Naur Form）で記述します。

### 宣言部

```c
%token BLACK
%token WHITE
%token LF
%%
// 規則部
%%
// プログラム部
```

今回は白と黒を示すトークンと、文の終わりを示す改行 `LF` トークンを使います。

### プログラム部（Lexer）

```c
static int yylex(YYSTYPE *yylval, YYLTYPE *loc) {
  int c = getchar();
  switch (c) {
    case '\n': return LF;
    case '0':  return WHITE;
    case '1':  return BLACK;
    case EOF:  exit(0);
    default:
      fprintf(stderr, "unknown character: %c\n", c);
      exit(1);
  }
}

int main() {
  printf("Input LULU the 48th: ");
  yyparse();
  return 0;
}
```

Lexer の役割として、一文字ずつ読んでトークンを判定するロジックを記述します。
通常は Lexer は別ファイルに分けますが、今回はシンプルなので直接 `yylex` 関数として定義します。

### 規則部

書籍を参考にオートマトンの状態遷移を描き、

![スライド：ルル語のオートマトンと規則部](/images/white-and-black-door/lulu_rules-25.png)

この状態遷移をそのまま文法規則として記述します。

```
input
  : S0 LF { printf("OK!\n"); }
  ;

S0
  : WHITE S1
  | BLACK S0
  ;

S1
  : WHITE S1
  | BLACK S2
  ;

S2
  : WHITE S1
  | BLACK S0
  ;
```

状態 `S0` から始まり、`0`（WHITE）を読むと `S1` へ、`1`（BLACK）を読むと `S0` に留まる……といった具合に、オートマトンの遷移をそのまま文法規則として表現しています。

### ビルド & 実行

```shell
lrama -d lulu.y -o lulu.c && gcc -Wall lulu.c -o lulu && ./lulu
```

Lrama で `.y` ファイルから C ファイルを生成し、コンパイルして実行します。

```
> Input LULU the 48th:
> 1001
> OK!
```
```
> 10011001
> OK!
```
```
> 101000101101
> OK!
```
```
> 1010
> syntax error, unexpected LF, expecting WHITE or BLACK
```

第四十八古代ルル語の判定器ができました。

### `--diagram` オプション

Lrama には `--diagram` オプションがあり、オートマトンの状態遷移図を HTML で出力できます。

```shell
lrama lulu.y --diagram
```

Lrama が出力した状態遷移図を眺めると、オートマトンの構造がよくわかります。

![Lrama の --diagram 出力](/images/white-and-black-door/lulu_diagram-28.png)

これを眺めると、最初に書いた正規表現 `^(0|1)*01$` よりも `^(1*0+1)*0+1$` のほうが、オートマトンの構造に即した表現であることがわかります。

## 文脈自由言語とプッシュダウン・オートマトン：第一古代クフ語

次はもう少し難しい規則を持った言語です。物語では「第一古代クフ語」として登場します。

```
I.   0011
II.  00001111
III. 00000001111111
```

規則は「`0` を n 回繰り返し、その後 n 回の `1` が繰り返される（n > 1）」です。

`0` に対応する `1` が存在することを確認するには **記録が必要** です。
正規表現では表現できない、再帰的な規則を持つ言語で、これを **文脈自由言語** といいます。
文脈自由言語は **プッシュダウン・オートマトン（PDA）** で表現できます。

第一クフ語の規則はこんな感じです。遺跡で表現すると、ちょっと複雑ですが、こんな感じになります

- 遺跡に入ると入れ物を手にする
- 入れ物には最初は「引換券」だけが入っている
- 入れ物の中のものは手前から順番に使う（LIFO/スタック構造）
- 引換券を使うと下記どちらかを選択し、右から順に入れ物に入る
  - 「白石・引換券・黒石」
  - 「白石・黒石」
- 石を使うと色に対応した移動が行われる

### 規則部

この引換券のルールをそのまま YACC の規則部に記述します。

```
input
  : S LF { printf("OK!\n"); }
  ;

S
  : WHITE S BLACK
  | WHITE BLACK
  ;
```

`S` が自身を含む再帰的な定義になっているのがポイントです。宣言部とプログラム部はルル語と同じです。

### ビルド & 実行

```shell
lrama -d kufu.y -o kufu.c && gcc -Wall kufu.c -o kufu && ./kufu
```

```
> Input KUFU the 1st:
> 0011
> OK!
```
```
> 00000001111111
> OK!
```
```
> 0001111
> syntax error, unexpected BLACK, expecting LF
```

`0` が 3 つなのに `1` が 4 つなのでエラー。ちゃんと対応関係を検証してくれています。

この再帰的な構造は、ネストした `if` と `end` の対応関係の判定にも使われます。プッシュダウン・オートマトンが Ruby の Parser でも活躍しているわけですね。

再帰的な入れ子構造が可視化されます。

# まとめ

- **Parser** は構文を解析して言語を判定するオートマトン
- **Lrama** は `parse.y` に定義された Parser を生成する Parser Generator
- 正規表現で表現できる**正則言語**は**有限オートマトン**で表現できる
- 再帰的な規則を持つ**文脈自由言語**は**プッシュダウン・オートマトン**で表現できる
